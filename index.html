Standardized Agent Loop

AI Coding Agent 的 4 步无损工作流

从探索到沉淀，全链路形成标准化记忆闭环。

01

先查记忆 (Recall)

探索前先问 cam。命中 latest 记忆直接复用，杜绝重复排查。

cam recall "<query>"
02

确认建图 (Index)

提示 not_indexed 时，执行一次 cam index 完成符号与调用边建图。

cam index
03

精准切片 (Read & Ref)

未命中时用 find 搜符号，read 读切片，ref 追溯调用链路。

cam read file/symbol
04

原子写回 (Add & Link)

解完后一条记忆存一条原子事实，用 --link 关联知识网络。

cam add --summary "..."

Frequently Asked Questions

常见问题解答

cam 与通用记忆框架（Mem0、Letta）有何不同？
通用对话框架面向日常聊天日志；cam 专为代码场景定制。内置 tree-sitter 代码图（支持符号切片与 1-hop 调用边），记忆与代码图共用本地 SQLite，专为编程原子事实与线性修订链设计，无需云端依赖或 Python 常驻服务。
为什么一定要区分主 Agent（MCP）与 Subagent（CLI）？
在 Cursor、Claude Code 等宿主中，主 Agent 委派子任务（Task/explore 或 Bash）时通常不向子进程传递 MCP。cam 提供双接口：主 Agent 调 MCP，Subagent 跑 cam --json，两者共享本地 .cam/cam.db，全链路无缝衔接。
纯离线断网环境下可以使用吗？
完全可以。无网络或无预训练模型时，cam 会自动平滑回退到词面 hash embedder，结合标识符感知 BM25 提供高精度的混合检索，零网络依赖。
什么是“虚拟路径”（Virtual Path）？
cam 独创的代码寻址机制。例如 src/main.rs 仅返回大纲；src/main.rs/main 精确返回该函数的源码切片。让 Agent 像查目录一样按需读代码，杜绝上下文浪费。
