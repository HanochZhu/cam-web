Standardized Agent Loop

AI Coding Agent 的统一 4 步循环

无论是 Cursor、Claude Code 还是轻量 Subagent，执行任何编码任务均遵循无损记忆闭环。

01

先 Recall 查记忆

探索代码前，把问题翻译成一句英文调用 cam_recall。若命中历史已沉淀方案且为 latest，直接复用，杜绝重复排查。

cam recall "<query>"
02

确认已建图

若提示 not_indexed，在项目根执行一次 cam index，tree-sitter 将自动解析函数、结构体、类与一跳调用边。

cam index
03

按图索骥精准读

记忆未命中时，通过 ls 或 find 锁定符号，使用 read 获取该符号切片，用 ref 追溯调用链路。

cam read file/symbol
04

原子事实写回

问题解决后，提取原子事实通过 add 记录关键方案（一记忆一事实）。相关事实用 --link 织成知识图谱。

cam add --summary "..."

主 Agent 与 Subagent 双门并立架构

主 Agent 通过 MCP stdio 调用工具；无法继承 MCP 的 Subagent 直接在终端跑 CLI。两者共享本地 .cam/cam.db，彻底解决多智能体协作断层。

原子事实与知识图谱连接

一条记忆严格存储一条原子事实，避免单条记忆信息过载。多个事实之间用 --link 建立知识图谱边，--parent 建立结构层级，--supersedes 建立线性修订版本链。

cam add --summary "..." --link ID_1 --link ID_2

艾宾浩斯抗遗忘衰减曲线

基于艾宾浩斯记忆模型计算保留率 \(R = e^{-t / S}\)，温和调节召回打分（幅度 \(\le 10\%\)）。每次真实命中强化稳定性（\(S \times 1.7\)）。记忆从不硬删除，过期条目标记为 needs_update。

Score = Relevance × (0.9 + 0.1 × R)

Frequently Asked Questions

常见问题解答

cam 与 Mem0、Zep、Letta 等记忆框架有何本质不同？
Mem0、Zep 等通用对话框架针对日常聊天日志与社交上下文设计；而 cam 专为代码场景定制。cam 拥有由 tree-sitter 驱动的代码图（精确到符号切片与 1-hop 调用边），记忆存储与代码图共用同一二进制和本地 SQLite，且专为编程中的“原子事实”与“线性修订链”设计，无需部署外部云服务或 Python 重型常驻服务。
为什么一定要区分主 Agent（MCP）与 Subagent（CLI）？
在 Cursor、Claude Code 等 IDE 中，当主智能体委派子任务（例如 Cursor 的 Task / explore 或 Claude Code 的 Bash 子会话）时，绝大多数宿主不会把 MCP 工具挂载给子进程。很多基于纯 MCP 的方案在子任务中立刻失灵。cam 采用双接口设计：主 Agent 调 MCP，Subagent 执行 cam --json，两者读写相同的 .cam/cam.db，保证全链路能力无死角。
离线环境下可以运行 cam 吗？
完全可以。默认嵌入模型（potion-multilingual-128M）在初次联网时缓存至 ~/.cam/models/；在纯内网或断网无模型环境中，cam 会自动平滑回退到词面 hash embedder，并结合原生 BM25 分词继续提供极高精度的混合检索，无需连外网。
什么是“虚拟路径”（Virtual Path）？
虚拟路径是 cam 独创的代码寻址机制。对于文件 src/main.rs，使用 cam read src/main.rs 仅返回该文件的符号大纲；而 src/main.rs/main 则是该文件内名为 main 的符号本身，只读取该函数的代码切片。这让 Agent 能像翻阅目录一样浏览代码，避免在上下文中加载大量无关实现。
